# 公开发布检查清单

本清单用于整理和验证一个待发布版本，不表示以下项目已完成。发布源码、发布 Python 安装包和部署运行服务是不同操作；准备副本不会自动执行 GitHub 推送或模型调用。

## 发布前需明确

- [ ] 确认本版本的 [MIT License](../LICENSE) 与 `Studio contributors` 署名，并保留第三方词表的独立许可；后续引入的新资源也须检查授权。
- [ ] 确认 Git 历史来源：迁移完整且已审查的历史，或为发布副本创建新历史。旧机器的 worktree `.git` 指针不是完整仓库。
- [ ] 确认公开文件清单不含运行数据、验收产物、凭据、个人配置或源机器路径。若保留历史，检查范围也须包含历史提交。
- [ ] 明确本版本实际验证的系统、Python、Codex CLI 和模型可用性；不把包安装成功当成模型调用成功。
- [ ] 记录必要测试的结果与未覆盖范围。环境失败、跳过和未执行都不能记为通过。

## 文件清单

应保留 `studio_runtime/`、`docs/`、`tests/`、`README.md`、`pyproject.toml`、启动器及相关项目文档。`studio_runtime/protocols/`、`static/` 和 `tokenizer_data/` 是运行依赖，需保留完整内容及第三方许可。

不得混入 `studio-data/`、`.validation/`、`snapshots/`、构建目录、egg-info、虚拟环境、Python/测试缓存、node_modules、个人 Codex 配置、环境秘密文件或旧 worktree 指针。需要公开演示时，另行制作或选用可公开的合成样例。

若副本已经建立 Git 仓库，提交前至少查看：

```sh
git status --short --untracked-files=all
git diff --check
git diff --cached --stat
git diff --cached
git ls-files
```

逐项审阅实际暂存内容，不只依赖忽略规则。秘密格式扫描也不能识别所有私人信息、用户材料或已失效凭据，需同时检查文本和二进制资源用途。

## 安装与验证

| 层次 | 检查内容 | 结果应记录什么 |
|---|---|---|
| 干净安装 | 新虚拟环境安装声明依赖，构建 wheel/sdist 并检查资源 | Python/依赖版本、安装产物、资源清单与错误 |
| 离线回归 | 七个顶层 Python suite；环境需允许本机回环监听 | 用例数、通过/失败/错误/跳过，完整依赖是否就绪 |
| 网页交互 | Node、Playwright、Chromium，合成 API | 浏览器版本与平台；不宣称完整后端端到端覆盖 |
| 模型兼容 | 在独立数据根目录用合成目标验证 Provider 和相关真实验收 | Codex CLI 版本、模型配置、实际调用与原始收据；可能消耗额度 |
| Windows 原生执行 | 涉及沙箱执行器的发布运行 `tests/native` | MXC 实际运行、隔离和失败场景；不能以离线替身代替 |
| 规模检查 | 需要时运行 `storage_scale.py` | 数据规模、机器环境、实际测量；不复用旧机器成绩 |

具体命令见 [测试说明](../tests/README.md)。测试在 `.validation/` 写入文件，应使用可丢弃的测试副本。验证后重新检查发布目录，避免把新生成的日志、构建文件和数据库加入提交或压缩包。

`doctor` 检查依赖与 Codex 版本/登录状态，不调用模型，但登录成功不能证明模型服务可用；`doctor --sandbox` 会实际运行固定原生沙箱探针。真实模型验收应单独安排，不能作为默认离线检查的隐式步骤。

## 文档与版本

- [ ] README 的启动命令、端口、数据位置和依赖与源码一致。
- [ ] 固定模型策略、本地存储与远端推理、Windows 专用沙箱的边界明确。
- [ ] 文档中的运行状态和恢复说明与实现一致，特别是网页提交输入会恢复运行。
- [ ] 包版本、运行格式和协议版本分别说明；不要仅凭主版本相同承诺旧数据续跑。
- [ ] 示例不包含个人路径、真实任务或不可公开的文件；仓库和联系链接只使用已存在的地址。
- [ ] 第三方许可随源码和相关分发资源保留。

## 可选的项目维护改进

仓库创建后，可按实际维护能力启用私密漏洞报告、添加 issue/PR 模板、设置离线 CI、整理变更日志和可重复依赖方案。这些配置不替代源码、历史、模型兼容性和原生沙箱的验证，也不应在尚未启用时写成已提供的承诺。
