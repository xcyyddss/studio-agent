# Python 测试执行与恢复

Studio 的 Python 工具执行的是明确选定的测试文件。模型不能提供 shell 命令、解释器路径或权限参数；正常角色调用仍不开放 shell。测试结果进入发起议题的输入队列，议题须说明如何使用结果，再继续作出判断。

## 环境与隔离

需要 Windows 上可用的 Codex 原生 MXC，以及启动 Studio 的 Python。工具使用宿主 PATH 中的 Codex 原生可执行程序和当前 Python；安装目录的合法联接会解析为物理路径，记录来源并在启动前核对。任务目录、输入文件、目标路径和执行账本仍禁止路径联接及符号链接，任务不能提供替代的可执行文件。

权限配置明确要求 MXC：文件系统默认拒绝，只允许读取必要平台运行时与 Python 安装，测试工作目录可写，网络关闭。环境变量按允许名单传递，不继承 API 密钥、代理变量或 PYTHONPATH。不自动安装软件、提权或降级为非隔离执行。宿主不支持 MXC、受管理权限拒绝或外层沙箱阻止启动时，返回明确诊断。[Codex Windows 沙箱说明](https://learn.chatgpt.com/docs/windows/windows-sandbox) 描述其宿主条件及权限机制。

执行前的固定探针只导入 unittest 并输出标记，不加载任务代码。探针成功仅表示执行环境可用。随后以相同的实际安装与权限配置执行固定的 Python -I -S -B unittest discovery，搜索 test_*.py；测试需要定义可发现的 unittest 测试。默认不加载 site-packages，不提供 pytest、pip 安装或联网下载。应用模块、包入口和所需数据须明确列入文件清单；子目录包须符合 unittest 的发现规则。

每个请求最多 32 个文件，仅支持非隐藏的 .py/.json/.txt/.csv/.md 目标；单文件默认 1 MiB，合计最多 2 MiB。执行默认 30 秒，可在请求中选择 1–60 秒。stdout、stderr 分别最多保存 64 KiB，超时或输出溢出会终止本次进程树并标记结果不明。没有声明 CPU、内存或磁盘配额。

## 执行与证据

1. 复制并记录输入文件的版本摘要，核对路径和目标冲突。
2. 固定探针检查 Codex、Python、MXC 和权限，保存原始输出、退出码与诊断。
3. 检查通过后保存实际调用，再运行测试。
4. 保存请求、结果和收据；同一请求重放只返回已保存结果，不再运行代码。
5. 结果作为定向输入交给原议题，包含退出码、测试计数、失败和错误、跳过数量、输出及读取文件范围。议题的 input_uses 记录承接用途和影响。

执行目录位于该运行的 tool-executions/请求摘要/。其中包含 request.json、result.json、receipt.json、sandbox-inputs.json、sandbox-preflight.json；实际启动后另有 sandbox-invocation.json 和 stdout.bin、stderr.bin。网页展示可读输出及收据路径。原始字节保留，文本显示采用 UTF-8 替换解码。

测试计数和标记来自不可信测试进程的输出，不证明测试内容充分或恶意代码不可伪造输出。测试全部跳过、没有发现测试，均不能作为验收成功；部分跳过会明确列出，是否覆盖关键要求仍须议题判断。缺少结束标记、异常提前退出、未提交完整账本均按结果不明处理。

## 失败与恢复

| 现象 | 含义 | 后续处理 |
| --- | --- | --- |
| 安装路径、固定探针或权限检查失败 | 测试尚未启动 | 修复宿主环境，再显式重试 |
| AssertionError、ModuleNotFoundError 等 | Python 已执行，代码或测试失败 | 议题分析输出，修改后创建新版测试请求 |
| 零测试、全部跳过 | 没有取得有效测试证据 | 修正测试发现或跳过条件 |
| 超时、输出溢出、提前退出、残缺账本 | 可能已执行部分代码，结果不明 | 查看保留证据，明确决定是否重新执行 |

未启动与结果不明的执行会形成实际的待恢复事项。它只进入所属议题的上下文，父议题可看到子树依赖；系统可以等待，但不能把该事项视为已经完成。网页允许“重新执行测试”，或附理由“结束恢复等待”。后一操作只结束等待，作为新的用户侧决定交给原议题，不生成测试通过结论。新返回结果仍须由议题实际处理。

重试会创建新的 TOOL 请求，记录 retry_of、理由和同版输入摘要；旧请求、输出和收据不覆盖。输入内容或账本完整性不符时拒绝重试；应为修改后的代码创建新的请求。重复点击同一个重试入口只返回已创建的后继请求。结果不明的执行不会自动重跑。

~~~powershell
python -B -m studio_runtime sandbox-check my-task
python -B -m studio_runtime retry-tool my-task TOOL.12 --reason "执行环境已修复"
python -B -m studio_runtime run my-task
~~~

结果不明时，检查记录后才给 retry-tool 加 --allow-uncertain。如不再需要该执行：

~~~powershell
python -B -m studio_runtime dismiss-tool-recovery my-task TOOL.12 --reason "该测试已被新的验证方案替代"
python -B -m studio_runtime run my-task
~~~

CLI 的恢复命令登记决定，run 继续执行；网页会接着启动工作。JOB 重试针对模型调用，TOOL 重试针对测试执行，两者不能互相替代。

## 数据兼容

新增诊断、恢复事项和重试链接均为追加记录；旧数据无需删除或重建。旧格式未记录执行阶段时，显示阶段未知，不推断它已经运行。历史结果、任务输入和产物原文保留。只读检查点不能检查沙箱或重试测试；需要先恢复为可运行副本。
